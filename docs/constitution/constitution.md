# Project Constitution

## Code Quality

- Use TypeScript for both frontend and backend changes.
- Avoid using any type whenever possible.
- Keep functions small and easy to understand.
- Follow the existing project structure instead of creating unnecessary folders.

## Testing

- Verify features manually before committing changes.
- Test room creation, room joining, gameplay flows using multiple browser tabs.
- Existing functionality is not broken after changes.

## Game Rules

- Game behavior should remain correct and follow the requirements.
- Scores should be calculated only according to the defined rules.
- Room data should remain isolated between different rooms.

## AI Usage

- AI suggestions should be reviewed before adding them to the project.
- Do not blindly accept generated code.
- Verify that generated code matches the specification and requirements.

## Review Discipline

- Make small and meaningful commits.
- Review changes before pushing.
- Keep implementation aligned with the specification, plan, and tasks.
