# Implementation Plan: Result Display & Restart

**Branch**: `004-result-restart` | **Date**: 2026-06-04 | **Spec**: `specs/004-result-restart/spec.md`

**Input**: Feature specification from `/specs/004-result-restart/spec.md`

## Summary

When a correct guess concludes a round, all players see a shared result state (secret word revealed, final scores, guess history). The host can then restart the game, returning everyone to the lobby with participants preserved and all round state cleared. Everything syncs via HTTP polling.

## Design Decisions (Research)

1. **Round conclusion trigger**: When `submitGuess` returns a correct answer, the round status transitions from `"drawing"` to `"complete"`. The room status transitions from `"active"` to `"result"`. This matches FR-001.

2. **Result state**: The existing `RoomSnapshot` uses `status: "result"` and `currentRound.status: "complete"`. The secret word is revealed to ALL viewers (no longer drawer-only). Scores and guess history are already in the snapshot from feature 003.

3. **Restart mechanism**: POST `/:code/restart` with `participantId` (host check). Clears `room.rounds`, `room.scores`, sets `room.currentRoundNumber = 0`, `room.status = "lobby"`. Participant list is untouched.

4. **Frontend result view**: GamePage watches `room.status === "result"` and shows a result overlay/screen with the word, sorted scores, and guess history. A "Restart Game" button appears for the host. Non-hosts see the result state without the restart button.

5. **No new frontend page needed**: The result state renders within the existing GamePage by branching on `room.status === "result"`. Lobby transition on restart happens naturally via polling (room.status becomes "lobby").
