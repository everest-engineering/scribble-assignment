# Implementation Plan: Result, Restart & Final Validation

**Branch**: `scribble-lab` | **Date**: 2026-06-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/004-result-restart/spec.md`

---

## Summary

Extend the room lifecycle with a new `"ended"` status. When the host ends the active round, the room transitions from `"active"` to `"ended"`, the word is revealed to all players, and all players are redirected to a result view showing the correct word, final scores, and full guess history. The host can then restart, which transitions the room back to `"lobby"` with participants preserved and all round state (word, drawer, strokes, guesses, scores) cleared. Two new backend endpoints (`POST /rooms/:code/end` and `POST /rooms/:code/restart`) drive the transitions. The frontend extends `GamePage` to conditionally render a result view when `room.status === "ended"`, with navigation logic handling all three status transitions: active → game view, ended → result view, lobby → lobby page.

**Project Type**: Brownfield web application extension

**Performance Goals**: All players see the result screen within ~2 seconds of the host ending the round; all players return to the lobby within ~2 seconds of the host restarting

**Constraints**: No WebSockets; polling only; no new npm dependencies; no timers or auto-end triggers; host-only round control

**Scale/Scope**: 2–10 players per room; result screen is ephemeral (cleared on restart)

## Implementation Slices

### Slice 1: Backend Status Extension (Blocking)

Extend `backend/src/models/game.ts`:
- Change `status: "lobby" | "active"` to `status: "lobby" | "active" | "ended"` on both `Room` and `RoomSnapshot`.

Extend `backend/src/services/roomStore.ts`:
- `toRoomSnapshot`: when `room.status === "ended"`, always set `currentWord: room.currentWord` (do not null it out for non-drawers). When status is `"active"` or `"lobby"`, preserve the existing viewer-scoping logic (`currentWord: null` for non-drawers).

---

### Slice 2: Backend New Endpoints

Add to `backend/src/api/schemas.ts`:
- `endRoomSchema`: `{ participantId: z.string() }`
- `restartRoomSchema`: `{ participantId: z.string() }`

Add to `backend/src/api/rooms.ts`:

**`POST /:code/end`**:
- Parse with `endRoomSchema`
- Look up room; 404 if not found
- 403 if `participantId !== room.hostId`
- 400 if `room.status !== "active"`
- Set `room.status = "ended"`, save, return `{ room: toRoomSnapshot(room, participantId) }`

**`POST /:code/restart`**:
- Parse with `restartRoomSchema`
- Look up room; 404 if not found
- 403 if `participantId !== room.hostId`
- 400 if `room.status !== "ended"`
- Reset: `room.status = "lobby"`, `room.currentWord = null`, `room.drawerId = null`, `room.strokes = []`, `room.guesses = []`, `room.scores = {}`
- Save, return `{ room: toRoomSnapshot(room, participantId) }`

---

### Slice 3: Frontend Types + API Client

Extend `frontend/src/services/api.ts`:
- Update `RoomSnapshot.status` type to `"lobby" | "active" | "ended"`
- Add `endRoom(code: string, participantId: string): Promise<{ room: RoomSnapshot }>` method
- Add `restartRoom(code: string, participantId: string): Promise<{ room: RoomSnapshot }>` method

---

### Slice 4: Frontend Store Methods

Extend `frontend/src/state/roomStore.ts`:
- Add `endRoom()` — calls `api.endRoom(code, participantId)`, updates room snapshot in store state
- Add `restartRoom()` — calls `api.restartRoom(code, participantId)`, updates room snapshot in store state

---

### Slice 5: Frontend GamePage Extensions

Extend `frontend/src/pages/GamePage.tsx`:

**Navigation logic** — replace the existing `useEffect` that navigates away on non-active status:
```
if (room.status === "active") → stay on page (render game UI)
if (room.status === "ended")  → stay on page (render result UI)
if (room.status === "lobby")  → navigate("/lobby", { replace: true })
// any other/undefined → navigate("/", { replace: true })
```

**Active game UI (existing)** — unchanged, but add:
- "End Round" button: visible only to the host (`isHost = participantId === room.hostId`) and only when `room.status === "active"`; clicking calls `roomStore.endRoom()`

**Result UI (new, conditional on `room.status === "ended"`)** — render:
- Section header: "Round Over"
- Correct word revealed: display `room.currentWord` prominently
- Final scoreboard: reuse `<Scoreboard>` component (already accepts `scores` + `participants`)
- Full guess history: reuse `<ResultPanel>` component (already accepts `guesses` + `participants`)
- "Restart" button: visible only to the host; clicking calls `roomStore.restartRoom()`

**Session restore**: No changes needed — existing `sessionStorage`-based restore already runs before any navigation guard; with the updated navigation logic, a player who refreshes while `room.status === "ended"` will remain on the result view.

## Data Flow Diagram

```
Host (Tab A) clicks "End Round":
  roomStore.endRoom() → POST /rooms/:code/end
    → room.status = "ended"
    → toRoomSnapshot returns currentWord to all viewers

All tabs (next poll ~2s):
  GET /rooms/:code → room.status === "ended"
    → GamePage navigation guard keeps them on the page
    → Result UI renders: word revealed, final scores, full guess history

Host (Tab A) clicks "Restart":
  roomStore.restartRoom() → POST /rooms/:code/restart
    → room.status = "lobby", currentWord=null, drawerId=null, strokes=[], guesses=[], scores={}

All tabs (next poll ~2s):
  GET /rooms/:code → room.status === "lobby"
    → GamePage navigation guard: navigate("/lobby")
    → LobbyPage shows all participants; host can start a new round
```
