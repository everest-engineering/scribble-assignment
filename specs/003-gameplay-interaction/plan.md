# Implementation Plan: Gameplay Interaction

**Branch**: `003-gameplay-interaction` | **Date**: 2026-06-04 | **Spec**: `specs/003-gameplay-interaction/spec.md`

**Input**: Feature specification from `/specs/003-gameplay-interaction/spec.md`

## Summary

Implement core gameplay loop: drawer draws/clears canvas (synced via HTTP polling), guessers submit guesses (trimmed, case-insensitive, empty rejected), guess history displayed to all, and scoring awards 100 points per correct guess. All state is in-memory; all sync uses HTTP polling (no WebSockets).

## Technical Context

**Language/Version**: TypeScript 5.x strict mode, Node.js 20+, React 18

**Primary Dependencies**: Express + Zod (backend), React 18 + react-router-dom v6 (frontend), tsx (dev runner), Vite (bundler)

**Storage**: In-memory (JS Map on backend)

**Testing**: vitest (backend unit), vitest + jsdom (frontend)

**Target Platform**: Modern browsers (frontend) + Node.js 20+ (backend)

**Project Type**: Web application (REST API backend + React SPA frontend)

**Performance Goals**: Canvas sync within 2s polling interval; guess validation + feedback <1s HTTP round-trip

**Constraints**:
- HTTP polling only — no WebSockets, SSE, or push protocols
- All state in-memory — no databases of any kind
- No authentication or sessions — participantId only
- Fail fast with descriptive errors (4xx/5xx with JSON body)
- Only basic black line drawing — no colors, brush sizes, shapes, or text

**Scale/Scope**: Small; single game rooms with 2–10 participants

## Design Decisions (Research)

1. **Canvas sync mechanism**: Store strokes as array of `{points: {x: number, y: number}[], color: string}` on Round. Drawer POSTs strokes after each stroke completes (mouseup). GET endpoint returns current strokes. Guessers poll and render.

2. **Guess storage**: Add `Guess[]` to Round model. Each guess has `participantId`, `text`, `isCorrect`, `timestamp`.

3. **Score storage**: Simple `Map<participantId, number>` on Room. Updated atomically when guess is correct.

4. **Correct guesser**: Once a guesser submits a correct guess, their subsequent guesses are recorded but `isCorrect` is still reported as true (no score increment). This matches the edge case "Guesser who already guessed correctly."

5. **Canvas rendering on guesser side**: Guessers render strokes by replaying the stored points via a `<canvas>` element. No pixel-buffer sync needed — stroke data is compact and suits polling.

6. **No new dependencies**: Canvas drawing uses native Canvas API + mouse events. No p5.js, Fabric.js, etc.
