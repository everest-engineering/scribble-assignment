# Implementation Plan: Gameplay Interaction

**Branch**: `scribble-lab` | **Date**: 2026-06-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-gameplay-interaction/spec.md`

---

## Summary

Add an interactive HTML canvas for the drawer, guess submission with trimming/case-insensitive comparison, synced guess history, and score tracking to the active game screen. All state (strokes, guesses, scores) lives on the `Room` model and is delivered to all clients via the existing `GET /rooms/:code` polling path extended with three new fields. Three new write endpoints handle drawing strokes, clearing the canvas, and submitting guesses. The frontend `GamePage` replaces its placeholders with a live canvas, a wired-up `GuessForm`, a `ResultPanel` showing guess history, and a `Scoreboard` showing per-player scores.

---

## Technical Context

**Language/Version**: TypeScript (strict) — Node.js 18+ backend, Vite + React frontend

**Primary Dependencies**: Express (backend), React + `useSyncExternalStore` (frontend) — no new libraries

**Storage**: In-memory `Map<string, Room>` — unchanged

**Testing**: Manual two-tab validation per `quickstart.md`

**Target Platform**: Browser (Chrome/Firefox/Safari)

**Project Type**: Brownfield web application extension

**Performance Goals**: Canvas and guess state visible to all clients within ~2 seconds of a change

**Constraints**: No WebSockets; polling only; no new npm dependencies; no `Math.random()` in game logic

**Scale/Scope**: 2–10 players per room; stroke list bounded to current round (cleared on game start)

## Implementation Slices

### Slice 1: Backend Data Model (Blocking — all other slices depend on this)

Extend `backend/src/models/game.ts`:
- Add `Stroke` interface: `{ points: Array<{x: number; y: number}>; color: string; lineWidth: number }`
- Add `Guess` interface: `{ id: string; participantId: string; text: string; correct: boolean; submittedAt: string }`
- Add `strokes: Stroke[]`, `guesses: Guess[]`, `scores: Record<string, number>` to `Room`
- Add same three fields to `RoomSnapshot`

Extend `backend/src/services/roomStore.ts`:
- `createRoom`: initialize `strokes: []`, `guesses: []`, `scores: {}`
- `toRoomSnapshot`: include `strokes`, `guesses`, `scores` in the returned snapshot
- `startRoom` caller (in `rooms.ts`): reset `strokes: []`, `guesses: []`; init `scores` from participants

---

### Slice 2: Backend New Endpoints

Add to `backend/src/api/schemas.ts`:
- `strokeSchema`: `{ participantId: z.string(), stroke: { points: z.array(...), color: z.string().optional(), lineWidth: z.number().optional() } }`
- `clearSchema`: `{ participantId: z.string() }`
- `guessSchema`: `{ participantId: z.string(), text: z.string() }`

Add to `backend/src/api/rooms.ts`:
- `POST /:code/stroke` — assert drawer, append stroke, save, return snapshot
- `POST /:code/clear` — assert drawer, reset strokes, save, return snapshot
- `POST /:code/guess` — assert guesser (not drawer), trim text, reject if empty (400), reject with 403 if the participant already has a correct guess in `room.guesses`, compare case-insensitively, create Guess, update score, save, return snapshot + guess

---

### Slice 3: Frontend Types + API Client

Extend `frontend/src/services/api.ts`:
- Add `Stroke` and `Guess` types
- Add `strokes`, `guesses`, `scores` to `RoomSnapshot` interface
- Add `submitStroke(code, participantId, stroke)`, `clearCanvas(code, participantId)`, `submitGuess(code, participantId, text)` API methods

---

### Slice 4: Frontend Store Methods

Extend `frontend/src/state/roomStore.ts`:
- Add `submitGuess(text)` — calls `api.submitGuess`, updates room snapshot in store
- Add `submitStroke(stroke)` — calls `api.submitStroke`, updates room snapshot in store
- Add `clearCanvas()` — calls `api.clearCanvas`, updates room snapshot in store

---

### Slice 5: Frontend Canvas Component

Create `frontend/src/components/DrawingCanvas.tsx`:
- **Drawer mode** (`isDrawer = true`): render an HTML `<canvas>` with pointer event handlers (`onPointerDown/Move/Up`). Collect stroke path on pointer-up, call `store.submitStroke(stroke)`. Show "Clear Canvas" button.
- **Guesser mode** (`isDrawer = false`): render a read-only `<canvas>` that redraws all `room.strokes` on prop change via `useEffect`.
- Canvas rendering: for each stroke, `beginPath()` → `moveTo(points[0])` → `lineTo(...)` per remaining point → `stroke()`.

---

### Slice 6: Frontend Component Wiring

**`GuessForm.tsx`**: Wire to `store.submitGuess(text)`. Client-side reject empty/whitespace text with inline message. Show "Correct!" or "Incorrect" on submit. Clear input on success. After a correct submission, hide the form permanently and show only the "Correct!" message. On session restore, derive already-guessed state from `room.guesses` (check for a correct entry from the current participant) and hide the form if the player already guessed correctly.

**`Scoreboard.tsx`**: Accept `scores: Record<string, number>` and `participants: Participant[]` as props. Render sorted list of name + score.

**`ResultPanel.tsx`**: Accept `guesses: Guess[]` and `participants: Participant[]` as props. Render each entry as `"{name}: {text} — Correct/Incorrect"`. Show empty state when no guesses.

**`GamePage.tsx`**: Replace canvas placeholder div with `<DrawingCanvas>`. Add game-phase polling (`setInterval` ~2s calling `store.fetchRoom()`). Pass `room.guesses`/`room.participants` to `ResultPanel`. Pass `room.scores`/`room.participants` to `Scoreboard`. Pass `isDrawer` to `GuessForm` to conditionally hide it.

## Data Flow Diagram

```
Drawer tab:
  pointer events → DrawingCanvas → store.submitStroke → POST /rooms/:code/stroke → Room.strokes updated
  "Clear" button → store.clearCanvas → POST /rooms/:code/clear → Room.strokes = []

Guesser tab:
  form submit → GuessForm → store.submitGuess → POST /rooms/:code/guess
    → Room.guesses appended + Room.scores[participantId] += 100 or 0

All tabs (polling ~2s):
  setInterval → store.fetchRoom → GET /rooms/:code?participantId=...
    → room.strokes  → DrawingCanvas re-renders
    → room.guesses  → ResultPanel re-renders
    → room.scores   → Scoreboard re-renders
```
