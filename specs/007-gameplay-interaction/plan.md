# Implementation Plan: Gameplay Interaction — Drawing, Guessing, and Scoring

**Input**: Feature specification from `/specs/007-gameplay-interaction/spec.md`

**Note**: This template is filled in by the `/speckit.plan` command. See `.specify/templates/plan-template.md` for the execution workflow.

## Summary

Provide an interactive drawing canvas (single black pen) for the drawer, guess submission with frontend+backend validation (trim, reject empty, case-insensitive compare), guess history and scoring synced via HTTP polling (correct=100pts, incorrect=0pts, no double-scoring). All gameplay interaction uses HTTP polling only — no WebSockets.

## Technical Context

**Language/Version**: TypeScript 5.6+ (ES Modules throughout)

**Primary Dependencies**: Express 4.21 (backend), React 18.3 (frontend), Vite 5.4 (build), Zod 3.23 (validation)

**Storage**: In-memory `Map<string, Room>` — no database

**Testing**: Vitest 3.x (both backend + frontend)

**Target Platform**: Node.js 18+ server, modern browsers (Chrome, Firefox, Safari)

**Project Type**: Web application (Express backend + React SPA frontend)

**Performance Goals**: Polling interval ~2s; canvas strokes transmitted as coordinate arrays (<1KB per stroke)

**Constraints**: <200ms p95 API response time; <100MB server memory; no WebSockets, no databases, no auth

**Scale/Scope**: Up to ~10 concurrent rooms, ~8 players each, single round per game session
