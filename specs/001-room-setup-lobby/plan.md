# Implementation Plan: Room Setup & Lobby

**Branch**: `001-room-setup-lobby` | **Date**: 2026-06-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-room-setup-lobby/spec.md`

---

## Summary

Add host tracking, player name validation, lobby auto-polling, and a host-guarded start-game
flow to the existing Scribble starter. The backend gains a `hostId` field on Room, a name
validation gate, and a new `POST /rooms/:code/start` endpoint. The frontend gains typed host
detection, replaces the manual refresh button with a `setInterval` poll, and gates the Start
Game control to the host with a player-count check.

## Data Flow

### Create Room

```
CreateRoomPage → api.createRoom(trimmedName)
  → POST /rooms { playerName }
  → roomStore.createRoom(playerName)
     → createParticipant(name)  [validates trim, throws 400 if empty]
     → room.hostId = participant.id
  → returns { participantId, room: RoomSnapshot { hostId, ... } }
  → RoomStore.setRoomSession(response)
  → navigate("/lobby")
```

### Lobby Polling

```
LobbyPage mounts
  → useEffect: setInterval(store.fetchRoom, 2000)
  → fetchRoom → GET /rooms/:code?participantId=...
  → setRoomSnapshot(room)
  → if room.status !== "lobby" → clearInterval + navigate("/game")
  → if 404 → navigate("/") with error
  → if 5xx/network → show inline error, continue polling

LobbyPage unmounts
  → clearInterval (useEffect cleanup)
```

### Host Guard

```
LobbyPage renders
  → isHost = room.hostId === participantId
  → canStart = isHost && room.participants.length >= 2

  if isHost:
    render <StartGameButton disabled={!canStart} />
    if !canStart: render "Need at least 2 players to start"
  else:
    render nothing (or permanently disabled button)
```

### Start Game

```
Host clicks Start Game
  → api.startRoom(room.code, participantId)
  → POST /rooms/:code/start { participantId }
  → roomStore.startRoom(code, participantId)
     → validate room exists → 404
     → validate participantId === room.hostId → 403
     → validate participants.length >= 2 → 409
     → room.status = "playing"
  → returns { room: RoomSnapshot { status: "playing", ... } }
  → navigate("/game")  [host navigates immediately]

Non-host polls → GET /rooms/:code → status === "playing"
  → clearInterval
  → navigate("/game")
```

## Implementation Sequence

Work through this order to keep each commit buildable and independently testable.

### Step 1 — Backend model + roomStore (types and host tracking)

Files: `backend/src/models/game.ts`, `backend/src/services/roomStore.ts`

- Expand `RoomStatus` to `"lobby" | "playing" | "result"`
- Add `hostId: string` to `Room` interface
- Add `hostId: string` to `RoomSnapshot` interface
- In `createRoom()`: set `room.hostId = participant.id`
- In `createParticipant()`: trim name; throw `HttpError(400, "Player name is required")` if empty
- In `toRoomSnapshot()`: include `room.hostId` in returned snapshot

### Step 2 — Backend API: start endpoint + schemas

Files: `backend/src/api/schemas.ts`, `backend/src/api/rooms.ts`

- Add `startRoomSchema = z.object({ participantId: z.string() })`
- Add `startRoom(code, participantId)` to roomStore
- Add `POST /:code/start` route in rooms router
  - 404 if room not found
  - 403 if `participantId !== room.hostId`
  - 409 if `participants.length < 2`
  - Transition `room.status = "playing"`; return updated snapshot

### Step 3 — Frontend type sync

File: `frontend/src/services/api.ts`

- Export `type RoomStatus = "lobby" | "playing" | "result"`
- Add `hostId: string` to `RoomSnapshot`
- Change `status: "lobby"` to `status: RoomStatus`
- Add `startRoom(code: string, participantId: string)` to `api` object

### Step 4 — Frontend store: startRoom action

File: `frontend/src/state/roomStore.ts`

- Add `startRoom()` method that calls `api.startRoom` with current room code and `participantId`

### Step 5 — Frontend: name validation in create/join pages

Files: `frontend/src/pages/CreateRoomPage.tsx`, `frontend/src/pages/JoinRoomPage.tsx`

- In `handleSubmit`: trim the player name; if empty after trim, set error state and return early
- In JoinRoomPage: also trim and reject an empty room code

### Step 6 — Frontend: lobby polling, host guard, start game

File: `frontend/src/pages/LobbyPage.tsx`

- Remove `handleRefresh` function and Refresh Room button
- Add `const POLL_INTERVAL_MS = 2000` constant
- Add `useEffect` with `setInterval`:
  - On each tick: call `store.fetchRoom()`
  - If returned room status is not `"lobby"`: clear interval and `navigate("/game")`
  - If fetch throws with a 404-style error: clear interval and `navigate("/")` with error
  - Otherwise: show inline error, keep polling
- Derive `isHost = room.hostId === participantId`
- Derive `canStart = isHost && room.participants.length >= 2`
- Render Start Game button only for host; disable with label when `!canStart`

## Risks

| Risk | Mitigation |
|------|-----------|
| `useEffect` interval fires after unmount | Cleanup via `clearInterval` in return function |
| Host navigates immediately but non-host poll hasn't fired yet | Non-host detects status change on next poll (≤2s delay is acceptable per spec) |
| TypeScript build breaks if RoomStatus change is not synced | Expand both sides in Step 1+3; run `npm run build` in both dirs as gate |
| `toRoomSnapshot` change breaks existing snapshot shape | Snapshot is additive (new field); no breaking change for existing consumers |
