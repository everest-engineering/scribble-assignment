# Implementation Plan: Result, Restart, and Final Validation

**Branch**: `008-result-restart-validation` | **Date**: 2026-07-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/008-result-restart-validation/spec.md`

## Summary

Add a `"result"` room status that displays the final round's correct word, cumulative scores, and guess history to all participants after the drawer ends the game. Provide a host-only "Restart" action that returns everyone to the lobby with participants preserved and all game state cleared.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 18+, ES Modules

**Primary Dependencies**: Express (backend), Zod (validation), React 18 + React Router v6 (frontend), Vite (build)

**Storage**: In-memory only (no database)

**Testing**: Vitest (both backend and frontend)

**Target Platform**: Web (modern browsers + Node.js server)

**Project Type**: Web application (monorepo with `backend/` and `frontend/`)

**Performance Goals**: Result state visible within one polling cycle (~2s) of game ending; restart reflected within one polling cycle

**Constraints**: No WebSockets (HTTP polling only); no databases; no authentication; all game state in-memory only

**Scale/Scope**: Small rooms (2-10 players), single-server, ephemeral sessions

## Phase 1: Design

### 1.1 Data Model

The `RoomStatus` type gains `"result"`. No new fields needed on `Room` — existing fields (`secretWord`, `scores`, `guesses`) are sufficient to represent the result state.

**Critical implementation notes:**
- `toRoomSnapshot()` must be modified: when `status === "result"`, include `secretWord` for ALL viewers (not just the former drawer). In result state, everyone should see the correct word.
- Existing gameplay endpoints (`addCanvasStroke`, `clearCanvas`, `nextWord`) check `participantId !== room.currentDrawerId` but **do not check `room.status`**. They must also reject with 400 when `status === "result"` to enforce FR-008.

State transitions:
```
lobby → drawing → result → lobby (restart)
```

- `drawing → result`: Triggered by drawer's "End Game" action. Room enters read-only result state.
- `result → lobby`: Triggered by host's "Restart" action. All round state cleared, participants preserved.
- In `result` status, all gameplay actions (draw, guess, Next Word) are rejected.

### 1.2 API Contracts

**End Game**: `POST /rooms/:code/end-game` with `participantId` query param → validates drawer, transitions to result, returns room snapshot with result data.

**Restart**: `POST /rooms/:code/restart` with `participantId` query param → validates host, transitions to lobby, clears state, preserves participants, returns room snapshot.

### 1.3 Frontend

- GamePage: Add "End Game" button (drawer only, during drawing status)
- ResultView component: Shows final word, scores, guesses, "Restart" button (host only)
- On poll detecting `status === "result"`: show result view instead of game view
- On poll detecting `status === "lobby"` after restart: navigate to lobby
