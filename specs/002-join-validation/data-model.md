# Data Model: Join Validation

**No changes to existing data model.**

This feature is limited to input validation on the join room flow. No new entities, fields, or relationships are introduced.

## Existing Entities (Unchanged)

### Room
- `code: string` — 4-character uppercase alphanumeric code (generated by `generateUniqueCode()`)
- `status: RoomStatus` — current room status (e.g., "lobby")
- `hostId: string` — participant ID of the room creator
- `participants: Participant[]` — list of participants in the room
- `createdAt: string` — ISO timestamp of room creation
- `updatedAt: string` — ISO timestamp of last update

### Participant
- `id: string` — UUID
- `name: string` — display name (defaults to "Player" if empty)
- `joinedAt: string` — ISO timestamp of join time
- `isHost: boolean` — whether this participant is the room host

## Validation Rules (New)

These are validation rules, not data model changes:

| Field | Rule | Location |
|-------|------|----------|
| Room code (client-side) | Must not be empty or whitespace-only after trim | `JoinRoomPage.tsx` — `handleSubmit()` |
| Room code (server-side) | Must not be empty or whitespace-only after trim | `schemas.ts` — `roomCodeParamsSchema.code: z.string().trim().min(1)` |
| Room code existence | Must match an existing room in the store | `rooms.ts` — `joinRoom()` returns null → 404 |
| Case normalization | Code is uppercased before lookup | Both client (`input onChange`) and server (`code.toUpperCase()`) |
